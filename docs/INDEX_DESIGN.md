# 菜单索引建议

## 推荐结构

以**菜名为主索引、食材类别为辅索引、原视频为证据**。先找到想吃的菜，再打开对应做法；同一条视频里的多道菜分别建立对应关系。

| 层级 | 内容 | 示例 |
|---|---|---|
| 主索引 | 规范菜名 | 姜葱炒鸡、肉酱意面、芒果西米露 |
| 辅索引 | 主食材或成品类别 | 鸡鸭禽肉、鱼虾海鲜、米饭面点、汤羹粥 |
| 场景标签 | 在视频中确认的使用场景 | 早餐、一人食、备餐、无油烟 |
| 证据定位 | 原视频链接与具体时间段 | BV12D4FzaEDY，01:08–01:18、01:39–02:08 |
| 配方记录 | 食材、用量、步骤、火候、缺失信息 | 未给克数就标注“未说明” |

## 当前实现

目前建立 9 类标题索引：鸡鸭禽肉、猪肉、牛羊肉、鱼虾海鲜、蛋豆蔬菜、米饭面点、汤羹粥、甜品饮品、调味与备餐。

当前标题索引词主要从标题提及的菜名和备餐词整理，尚不是逐条观看后的完整菜谱。标题可能同时提到对比菜式，索引命中仍需回看核验。已核菜谱正文提供与字幕、画面核对后的时间点。

## 保留与剔除规则

1. 展示烹饪、食材加工、调味或实际备餐的条目保留。
2. 混合生活记录中只要有可用做菜片段就保留，记录具体时间段。
3. 只有旅游、购物、外出吃饭、酒店展示而没有做菜内容的，核对后剔除，并保留理由与原链接。
4. “新作上线”等含糊标题不能直接判断，保留为待核内容。
5. 标题有做菜线索只代表初筛通过，不能自动改成已核做菜。

## 同名与变体

同名菜保留多个视频版本。可以把“糖心蛋”与“溏心蛋”等常见写法合并到同一检索名，但不可因此合并两条视频的配料。盐焗味、沙姜味、不同器具和不同火候应作为版本差异保留。

## 后续补充字段

每条菜谱建议增加 `recipe_id`、`dish_name`、`variant`、`video_bvid`、`start_seconds`、`end_seconds`、`ingredients`、`amounts`、`steps`、`heat`、`duration`、`missing_details`、`review_status`。菜谱与视频用 BV 号关联，不依赖标题或表格行号，便于增量更新和纠错。

## 下一批优先顺序

先核对 68 条标题含糊的视频，再处理菜单索引尚未覆盖的条目。随后按用户常做的菜或出现较多的菜分批补配方。每次更新保留已核、待核和剔除状态，让阶段成果可以独立使用。
